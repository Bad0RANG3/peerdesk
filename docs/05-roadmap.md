# 路线图

当前版本 **0.9.0**。本文只记录原生 C++/Qt 阶段的现状、验收门槛和下一步优先级，
不再保留旧运行时、旧抓屏方案和旧打包流程的历史。

标记：`[已完成]`、`[进行中]`、`[待开始]`。只有被测试或真实验收证明的能力才能标成
已完成。

## 1. 当前基线

- `[已完成]` **统一原生技术栈**：CMake、C++20、Qt 6.8 Widgets；服务端、传输、
  会话、Windows 平台层和客户端在同一仓库构建。
- `[已完成]` **三个原生可执行程序**：`peerdesk-server`、`peerdesk-client` 和
  `peerdesk-link-harness`。
- `[已完成]` **连接与信令**：9 位连接码、3-3-3 显示、TCP JSON Lines 信令、
  STUN 候选、UDP 打洞、6 秒中继升级、令牌和每 IP 连接频次限制。
- `[已完成]` **数据面**：X25519、基于 HMAC-SHA256 的提取-扩展派生、每包 AEAD、
  重放窗口、视频 FEC/NACK、控制可靠流和 G.711 音频。
- `[已完成]` **桌面能力**：GDI 抓屏、多显示器、被控端独立媒体线程内的缩放/静帧检测/
  JPEG 编码、Viewer 独立 JPEG 解码、视频分片/FEC/NACK 重传缓存检索工作线程、
  WASAPI loopback、Win32 键鼠、文本剪贴板、带发送中取消与断线续传的双向文件传输，
  以及 Viewer 与被控端可重试多文件队列。
- `[已完成]` **游戏鼠标（回环）**：相对捕获、16 ms 合帧、独立相对按键、
  Windows 边缘回中、`Esc` 退出和断线/结束释放；真实游戏兼容性仍待跨机验收。
- `[已完成]` **Qt 应用壳**：连接页、被控端页、Viewer、设置、系统托盘、窗口几何
  持久化、160 ms 淡入淡出并自动隐藏的工具栏和合成 Viewer 演示。
- `[已完成]` **单实例与窗口唤回**：普通模式通过用户级锁保证单实例，二次启动用本机
  命名管道恢复并激活已有窗口；截图、合成采集、合成音源和 demo 保持隔离并行。
- `[已完成]` **登录启动（回环）**：设置页维护当前用户
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `PeerDesk` 值，命令为
  带引号的绝对路径加 `--background`；后台模式参与单实例、自动开始被控并在托盘可用时
  隐藏窗口，托盘不可用时回退显示。平台注册表与 UI 开关已有自动化测试。
- `[已完成]` **最近连接**：仅在成功进入实况后记录最近 4 个对端，按“连接码 + 服务器”
  去重并置顶；点击回填连接码和服务器，不覆盖令牌，不自动连接；支持清除，记录仅在本机。
- `[已完成]` **Windows CI**：配置、编译并运行全部 CTest；本地使用 `windows-mingw`
  preset，CI 使用 `windows-mingw-ci`。独立打包任务使用 Release preset 生成安装包，
  并执行静默安装、离屏启动截图和静默卸载冒烟。
- `[已完成]` **Windows 安装/卸载（本机冒烟）**：Inno Setup 每用户安装，不需要管理员
  权限；部署客户端、服务端、Qt/MinGW 运行库、中文关键向导文案、开始菜单快捷方式和
  可选桌面快捷方式。卸载清理程序文件、快捷方式和登录启动项，保留用户偏好与接收文件。
- `[已完成]` **Viewer 断线恢复（回环）**：信令自动重连、同码重配对、重新握手、
  保帧、输入隔离、30 秒恢复期限和最终失败分流均有自动化测试。
- `[已完成]` **文件断线续传（回环）**：接收端按旧传输 ID、文件名、大小和 10 分钟
  保留期校验断点，返回实际偏移；发送端确认前不发数据，确认后只发送尾部。Host 自动
  续传，Viewer 队列保留进度并在恢复实况后继续。
- `[已完成]` **日志与诊断**：客户端/服务端滚动文件日志、UTC 时间/级别/PID/线程 ID、
  4 MiB × 5 轮转、设置页打开日志目录、脱敏 ZIP 诊断包、异常退出提示和客户端日志隔离。
  诊断包只在本机生成，不自动上传，不含 minidump。
- `[待开始]` **真实跨机验收**：两台 Windows 主机的直连、中继、弱网、多屏、
  文件和长会话仍需独立完成。
- `[待开始]` **真实登录启动验收**：在真实 Windows 用户注销/重启、托盘不可用和
  重复启动场景验证启动项、后台驻留与窗口回退。

## 2. 测试基线

当前 CTest 注册 13 个套件：

| 套件 | 覆盖重点 |
| --- | --- |
| `peerdesk-core` | 包头、JSON、分片、FEC、音频载荷和基础工具 |
| `peerdesk-crypto` | X25519、派生、AEAD、nonce、重放窗口 |
| `peerdesk-transport` | 视频重组、NACK、控制流和 ACK 语义 |
| `peerdesk-stun` | Binding Request/Success、地址解析和 XOR 地址 |
| `peerdesk-server` | 信令、注册、配对、令牌、限流、STUN、中继 |
| `peerdesk-peer-link` | 握手、候选、直连/中继、保活、链路状态和视频发送流水线 |
| `peerdesk-session` | 被控/控制会话、双向独立媒体线程、JPEG 编解码、设置、音频、文件和输入事件 |
| `peerdesk-signaling-client` | TCP JSON Lines、重连策略和消息映射 |
| `peerdesk-app-controller` | 控制器生命周期、偏好、最近连接持久化、错误和 UI 门面 |
| `peerdesk-single-instance` | 锁互斥、跨进程唤醒、重复实例拒绝和异常退出后重获锁 |
| `peerdesk-ui` | 连接码、校验、最近连接回填/清除、页面切换、Viewer 输入、双向文件队列、托盘语义和登录启动开关 |
| `peerdesk-logging` | 日志轮转、敏感值/端点/路径脱敏、诊断包内容与大小限制、异常退出标记 |
| `peerdesk-platform` | GDI、WASAPI、Win32 输入、剪贴板、重采样和当前用户启动项 |

本地命令：

```powershell
cmake --preset windows-mingw
cmake --build --preset windows-mingw
ctest --preset windows-mingw --output-on-failure
```

CI 命令使用对应 preset，并要求全部 13 个套件通过。回环测试和合成画面只能证明代码路径，
不能替代真实跨机网络和长时间稳定性验收。

## 3. 优先级路线

### P0：先补正确性和恢复能力

1. `[已完成]` **信令重连**：Viewer 在 `offline`/`not_found` 时保留角色，按指数退避
   重新配对；TCP 断开后自动重连并重新注册。
2. `[已完成]` **会话恢复**：实况链路中断后停止旧会话、释放输入、保留末帧，同一连接码
   重新配对并握手；Host 回到 `Waiting` 保留注册。
3. `[已完成]` **选择性 ACK 修复**：把位图语义统一为
   `bit i = cumulative + 1 + i`，修复接收窗口对空洞的表达。
4. `[已完成]` **ACK 回归测试**：覆盖乱序、重复、越界、伪 ACK、重传上限和连接重置。
5. `[已完成]` **恢复 UI**：实况断线时显示“正在恢复”遮罩、隐藏返回按钮和工具栏，
   保留最后一帧；最终失败才显示结束页。

回环验收门槛已满足：同码重配对恢复、保帧、输入只释放一次、恢复超时和挂断静默均有
控制器/UI 测试。真实断网、NAT、弱网和长会话下的同一门槛仍归 P1，不能用回环结果代替。

### P1：两台真实 Windows 主机验收

这不是回环测试可以替代的阶段。至少需要：

- 同一局域网直连。
- 不同 NAT 环境下的打洞成功与失败。
- 强制中继、低带宽和高延迟。
- 故意丢包、抖动、短时断网和恢复。
- 两个显示器和切换。
- 文件双向传输、同名文件、非法文件名和大文件边界。
- 声音开关、长时间静音和恢复播放。
- 至少一场长会话，观察内存、线程、重传、丢帧和 UI 状态。
- 两台主机的 Windows 10/11 组合、高 DPI 和不同桌面缩放。
- 注销/重启后的登录启动、托盘驻留、单实例唤醒和托盘不可用时的窗口回退。

验收产出必须包含环境、拓扑、时间、网络条件、结果和失败复现步骤。只有真实数据才能
更新“体验接近”的结论。

## 4. 暂不承诺

以下事项尚未完成，不得在发布说明中写成已支持：

- 真实跨 NAT、弱网和长时间信令中断下的恢复结论，以及跨机文件续传和媒体断点续传。
- 真实跨机、NAT 全组合、弱网和长时间稳定性结论。
- 安装包代码签名、自动更新、失败回滚、跨版本升级结论，以及真实登录/重启后的启动项验收。
- H.264、Opus、虚拟显示器、虚拟 HID 和广泛游戏兼容性。
- 线程池、GPU 编码、硬件编码或正式性能指标。
- 与网易UU远程完全等价的产品体验。

## 5. 发布判断

一个阶段只有同时满足以下条件才推送和标记完成：

1. 相关代码和文档在同一提交内。
2. 本地不覆盖未完成的并行工作；必要时只暂存阶段文件。
3. Windows CI 配置、编译和全部 CTest 通过。
4. 涉及发布包时，安装包生成和静默安装/启动/卸载冒烟通过。
5. 没有把未实现能力写进 README、路线图或 UI 文案。
6. 跨机阶段必须有真实验收记录，不能用回环或合成截图代替。
